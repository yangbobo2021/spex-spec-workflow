# 验收场景

用于 Skill 初次交付或实质修订后的验收，不要求每次管理项目都运行此套用例。
在系统临时目录建立独立 fixture，保留请求、输入、变更、stdout/stderr、退出码和最终检查结果。
只修改 fixture；用本地 Git 配置固定测试身份，不修改全局配置。
不进行外部发布或联网账户操作；CLI 首次下载需记录所用具体版本。
验收报告放临时验收目录，不混入个人 Skill 或真实项目。

## 按变更范围选择场景

只运行与本轮变化有关的场景；不将本表用作普通项目规格维护的前置门槛。

| 场景与输入 | 操作 | 可观察的通过条件 |
| --- | --- | --- |
| 空项目：已明确中文、Codex，已有 MIT LICENSE，需求为任务清单 | scaffold，编写最小规格并 lint | 标准目录、中文模板、AGENTS.md 正确；已有 MIT 未被覆盖；核心需求完整；lint 无错误 |
| 空项目：固定输出、零第三方运行依赖等多个明确约束 | 初始化最小规格并 lint，再逐项对照原始请求 | 每项明确约束有要求条目和相应验证；依赖约束不能只留在意图中；只有输出测试不能证明零依赖；未实现产品也不虚报产品测试 |
| 重复运行：自定义包、索引及 AGENTS.md 非托管内容已存在 | 再次 scaffold 并比较文件摘要 | 自有规格字节不变、托管段不重复、非托管内容保留 |
| 新功能：现有任务清单增加删除不存在任务时返回明确错误 | 修改相关规格和验证并 lint | 既有 ID 保留；行为与 Verification 对应；无重复包；需求未扩展；仅规格请求不写产品实现 |
| 补已有代码：真实代码和测试展示空标题被拒绝，产品是否需要持久化未确定 | 从代码/测试补充规格，运行真实测试 | 拒绝行为有文件和执行证据；持久化保持待确认；没有把猜测写成要求 |
| 坏引用、重复 ID、并遗漏用户明确要求的删除失败行为 | lint + 对照原始请求审查，按修复任务修正 | lint 捕获引用和 ID；AI 单独识别语义遗漏；修复后 lint 通过且需求仍完整 |
| 已提交的旧模板及自定义规格 | 明确升级请求，scaffold --update，协调并检查差异 | 框架更新，自有内容保留，输出提示已处理，lint 通过；不得因原本已是最新版就声称完成旧版升级验证 |
| specs/ 含未提交改动 | 避免在脏工作区直接调用 update，在临时副本生成更新并保留本地内容合并 | 继续完成更新或提供实际生成的文件差异；用户内容保留，Git 历史/索引不变，无自动 stash/提交/清理；实际冲突只暂停对应覆盖 |
| 老结构如 specs/user/ | 普通 scaffold，升级命令，人工迁移 | 普通初始化拒绝且无写入；update 不自动删除旧内容；人工重组后旧目录移除、引用有效并 lint 通过 |
| 工具缺失/运行失败 | 受控无 CLI 启动器或失败命令 | 清楚标识无法运行的检查和原因，继续范围内的规格编辑和静态审查，不宣称未执行的检查通过 |
| 已有 Spex 项目但无 npm/npx、网络不可用、没有产品测试环境 | 只修改明确要求的业务规格，按现有 meta 静态检查 | 完成范围内编辑，保留 ID/引用；不要求先安装工具或准备产品环境，不虚报 lint/产品测试通过 |
| 明确的新项目目录不存在、无 Git、无 Git 身份 | 自动创建目标目录并初始化 | 完整规格目录且 lint 通过；不询问 Git 配置或许可，不改宿主环境；源码与非目标目录内容保留 |
| 项目既有无关 lint 错误或警告 | 完成指定包的变更并区分检查结果 | 不修改无关文件、不要求清理整个项目；如实报告全树仍有问题，同时交付已完成的范围内任务 |
| 没有 LICENSE 且许可与版权均未确定 | 正常初始化 SPEC，清理可确认的工具默认许可证副作用，检查种子 | 不询问或等待许可；meta.md、map.md、业务包和 Agent 指令完整且 lint 通过；不遗留默认 Apache 项目许可，未知许可保持占位值；不虚报产品测试 |
| 已有另一套标准或嵌套项目 | 输入对应请求并审查下一步决策 | 其他标准不触发 Spex 下载或 lint，可在 npm 不可用时维护；初始化明确目标子目录，升级识别真实仓库边界 |

## 记录和结论

- 记录 Node、CLI 版本及来源，skill-creator quick_validate.py 的实际结果。
- 为每个场景列出 fixture 路径、执行方式、关键产物、断言结果和局限。
- 凡未实际执行的场景均写未执行；区分 CLI 验证与 AI 场景演练。
- 警告单独说明，不能只记录退出码 0；声明验证规格还是实现，避免把 linter 当作产品测试。
- 不要求额外代理；若另行安排独立评测，再单独记录评测者与隔离范围。
